# SafePath 경로 신뢰성 개선 보고서

작업일: 2026-11-14. 요청된 보관 위치인 바탕화면/캡스톤 작업 보고서/2026-11-13 폴더에 추가 저장한다. 본 보고서는 이전 경로 알고리즘 보고서의 안전 점수·네트워크·반복 경로 판정 부분을 대체한다.

대상: C:/Users/pc/safepath-audit-20261113-front의 휴대폰 앱. 기존 검색 → 경로 추천 → 출발 준비 흐름, 드래그 패널, 중복 경로 이름만 표시하는 상단 안내는 유지했다. wear 모듈과 워치 연동 구현은 수정하지 않았다.

개선 1 - 구간별 안전 참고 지표: 시설 총량·밀도 대신 10m 이하 구간의 시설 인접 비율, 전체 시설 공백 길이, 가장 긴 연속 시설 공백을 평가한다. 특정 장소의 CCTV 개수만 늘려 전체 경로가 안전해 보이는 문제를 막았다.

개선 2 - 보행 도로 연결 검증: 출발·도착 스냅 반경 75m, 중간 경유지 40m를 API 요청에 명시하고 반환 좌표도 재검증한다. 잘못된 종점, 누락된 스냅 근거, 비정상 거리·시간·좌표 응답은 경로로 채택하지 않는다.

개선 3 - 반복 경로 비교: 모든 반복을 무조건 삭제하던 방식에서 기본 보행 경로와 우회 후보를 비교하도록 변경했다. 깨끗한 대안이 있으면 반복 후보를 제외하고, 기본 연결 자체에 회귀가 있는 경우 기본 경로를 보존하면서 왕복 포함을 표시한다.

개선 4 - 실제 API 검증 및 성능: 앱과 동일한 Kotlin 경로 엔진을 PC JVM에서 실행해 공개 장소 인근 12개 사례를 조회했다. 개인 GPS는 사용하지 않았고 API 키는 보고서·결과 파일에 기록하지 않았다.

최종 검증: 오프라인 회귀 테스트 65개 통과, 실패 0개·오류 0개. 선택 실행용 실제 API 테스트 1개는 일반 실행에서 제외한 뒤 별도로 실행해 통과했다. APK 빌드 성공. 실제 API 경로 생성 11/12, 품질 제한 위반 0건.

판정: 기존보다 실패 처리와 검증 근거가 강화된 시험 가능한 베타다. 이 결과만으로 일반 사용자에 대한 현장 안전성·상용 출시 적합성이 입증된 것은 아니다. 야간 보행, 잠긴 출입구, 시설 가동 여부, 휴대폰 실측은 별도 검증이 남는다.

# 구간별 시설 안전 참고 지표의 작동 방식

탐색 범위는 요청대로 출발·도착 직선의 중점 중심, 직선거리의 2배 반경이다. 원 안의 모든 CCTV·보안등을 사용한다. 시설 자료를 모으는 원형 범위와 실제 도로의 연결은 구분한다. 교량 진입 등으로 도로가 원 밖을 잠시 통과한다는 이유만으로 유효 경로를 버리지 않는다.

기존 고정 33×33 격자를 거리별 격자로 바꿨다. 목표 간격은 50m이며 계산량을 위해 최대 101×101이다. 직선거리 1km에서는 간격 약 50m, 5km에서는 약 200m다. 격자 시설 누적값을 셀 면적으로 보정해 긴 검색일수록 시설 영향이 임의로 커지는 현상도 줄였다.

실제 도로의 경로 선분을 최대 10m 간격으로 나눈다. 각 구간의 중점이 CCTV 50m 또는 보안등 40m 안이면 시설 인접 구간으로 센다. 모든 구간은 실제 길이로 가중한다. API 꼭짓점이 촘촘한 도로가 더 높은 점수를 받지 않는다.

C = CCTV 인접 길이 / 총 경로 길이. L = 보안등 인접 길이 / 총 경로 길이. U = 둘 중 하나 이상이 인접한 길이 / 총 길이. G = 가장 긴 연속 시설 공백(m), M = 전체 시설 공백 길이(m).

시설 지표 S = 100 × (0.45U + 0.35L + 0.20C) × exp(-G/500) × exp(-M/2000). 범위는 0~100이다. 시설이 전혀 없는 구간은 개수로 상쇄되지 않으며 긴 공백과 긴 노출이 각각 감점된다. 같은 위치의 카메라 개수만 늘려도 인접 길이가 변하지 않으면 점수는 같게 유지된다.

안전 경로는 S 최대, 동점이면 예상 시간이 짧은 후보를 선택한다. 최단은 API 예상 시간 최소다. 추천은 0.65×(S/100) + 0.35×(가장 빠른 후보 시간/해당 후보 시간)으로 결정한다. 후보들의 최소·최대 점수로 재조정하지 않아 무관한 느린 후보가 추가돼도 평가 척도가 흔들리지 않는다.

이 공식의 반경과 가중치, 공백 감점 상수는 초기 공학적 설정이다. 범죄 통계나 야간 현장 자료로 보정된 확률 모델이 아니다. 인접 시설은 실제 촬영 범위·조도·벽 너머 접근성·시설 가동 상태를 보장하지 않는다. UI에도 시설 자료 기준임을 표시했다.

# 도로 검증·반복 구간·시간 제한

도로 연결: Mapbox walking에 radiuses를 좌표별 75m(출발·도착), 40m(경유지)로 보낸다. waypoints_per_route=true로 반환된 각 스냅 좌표를 요청 좌표와 Haversine 거리로 비교한다. 실제 경로의 양 끝도 요청 위치 75m 이내여야 한다. 15m 초과 연결은 카드에 연결 거리를 표시한다.

응답 검증: LineString 형식, 유한 위·경도 범위, 최소 2개·최대 30,000개 좌표, 양수 거리·시간, 전체 선 길이 100km 이하, 반환 거리와 실제 선 길이의 오차(30m 또는 15% 중 큰 값 이내)를 검사한다. 대안 한 개의 응답이 깨져도 다른 유효 경로는 유지한다.

경유지 생성: 방향 전환점을 간소화하고 출발·도착 30m 이내의 불필요한 강제점, 목적지 초과·역방향 강제점을 제거한다. 내부 경유지는 최대 8개이며 실제 보행 API가 다시 연결한다. 표시용 선분을 잘라 붙여 지름길을 만들지 않는다.

반복 진단: 약 5m 간격 표본으로 이전 진행선과 3m 이내, 비슷한 축으로 재통과하는 길이와 최대 반복 길이를 측정한다. 40m 이상 이동 후 기존 꼭짓점 1m 이내로 돌아오는 닫힌 우회도 진단한다. 가까운 평행 길이나 단일 교차를 무조건 왕복으로 보지는 않지만 도로 ID·층 정보가 없는 좌표 근사이므로 오탐 가능성은 남는다.

반복 처리: 깨끗한 기본 대안이 있으면 이를 우선한다. 우회 후보가 기준 경로보다 반복 길이를 15m 이상 늘리거나 닫힌 우회를 추가하면 제외하고 경유지를 줄여 한 번 재조회한다. 깨끗한 최종 대안이 생기면 반복 후보를 배제한다. 모든 연결에 회귀가 남으면 검증된 기본 경로를 보존하고 왕복 포함을 표시한다. 불가피함을 현장 수준에서 확정했다고 주장하지 않는다.

성능: HTTP 호출 전체 제한 4초, 기본 조회 예산 4.5초, 우회 정교화 예산 6초, 전체 검색 예산 12초를 둔다. 우회 요청은 최대 2개 동시 실행한다. 취소 시 HTTP Call도 취소한다. 전체 시간이 초과돼도 이미 검증한 기본 경로가 있으면 시설 분석 미완료를 표시해 복구한다.

캐시: API 결과를 메모리에만 2분 보관하고 최대 16항목·좌표 합계 50,000개로 제한한다. 로그인 키가 바뀌면 다른 클라이언트를 사용한다. 시설 자료 로딩 실패는 빈 자료로 영구 캐시하지 않고 기본 경로와 자료 확인 불가 상태를 반환한다. 물리적 OS·파일 I/O 지연까지 실시간 보장하는 것은 아니다.

# 검증 범위·재현 방법·남은 조건

일반 테스트는 앱 및 Wear SDK 화면을 띄우지 않는 JVM 회귀 테스트다. 실제 API 테스트는 같은 RouteSearchEngine·MapboxWalkingClient·WalkingRouteProtocol·시설 평가기를 사용한다. 수식만 별도 Python으로 흉내 낸 검증이 아니다. 공공시설 CSV는 테스트 시작 전에 읽어 메모리에 둔다.

테스트 사례: 도심·하천 인근·역/시장·교량·공원 인근·캠퍼스·여러 지역 좌표를 지정했다. 지명은 주변 사례 구분용이며 현장을 답사해 보도·출입구 상태를 확정한 것은 아니다. 12개는 통계적으로 충분한 서비스 품질 표본이 아니다.

재현 명령(프로젝트 루트): ANDROID_HOME을 설정한 뒤 gradlew.bat :app:testDebugUnitTest :app:assembleDebug --no-daemon. 실제 API는 환경변수 SAFEPATH_LIVE_VALIDATION=1을 설정하고 gradlew.bat :app:testDebugUnitTest --tests *LiveRouteValidationTest* --no-daemon으로 선택 실행한다. 로컬 Mapbox 키가 필요하며 기본 테스트에서는 외부 호출을 하지 않는다.

근거 파일: docs/week11/validation/unit-test-summary.json, live-route-validation.json, park-snap-diagnostic.json. 변경 코드: RouteSafetyEvaluator.kt, WalkingRouteClient.kt, RouteSearchEngine.kt, FacilityRoutePlanner.kt, RouteContinuity.kt, NavigationRepository.kt 및 경로 카드. 기존 시설 CSV 자체는 이번 신뢰성 개선에서 추가 변경하지 않았다.

현재 남은 한계: 전체 보행 도로망을 직접 탐색한 전역 최적해는 아니다. 시설 격자에서 찾은 우회 후보를 실제 도로로 연결해 평가한다. 벽·층·사유지·출입시간·시설 가동·조도 자료가 없으므로 시설의 실제 보호 효과는 미검증이다. 자료 공백은 위험 확정이 아니라 자료상 미관측으로 해석해야 한다.

상용 사용 전 필요한 검증: 실제 휴대폰·LTE/Wi-Fi·저사양 환경의 검색 시간과 취소 동작, 더 많은 지역 및 장거리 도보 사례, 막다른 골목·입체 교차·출입 제한 장소의 현장 대조, 야간 시설 상태와 점수 상수 보정. 현장 보행 안전성의 검증은 이번 환경에서 수행할 수 없었다.

GitHub 커밋·푸시·배포는 하지 않았다. 휴대폰 앱의 테스트용 APK를 빌드했고 wear 변경은 없다. 새 로컬 테스트 화면·버튼은 만들지 않았다. 실제 귀가 세션·SOS 서버 계약 등 이전에 미구현으로 남긴 기능은 이번 경로 엔진 작업으로 완료된 것이 아니다.

공식 API 근거: https://docs.mapbox.com/api/navigation/directions/ 의 radiuses, waypoints_per_route, continue_straight, 응답 code 설명. 시간은 추정 이동시간이며 실제 현장 안전성이나 도착 시간을 보장하지 않는다.
