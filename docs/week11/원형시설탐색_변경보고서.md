# 원형 시설 탐색 기반 경로 생성 - 변경 보고서

2026-11-13 | 본 문서는 같은 날짜의 기존 11주차 보고서 중 경로 생성 설명을 보완·대체한다. 기존 앱 흐름, 추천 → 안전 → 최단 표시 순서, wear 및 파출소 위치 제외 조건은 유지했다.

변경 요구: 출발지 A와 목적지 B를 잇는 가상 직선의 중점을 C로 두고 직선거리 d의 2배를 반경으로 한다. d=1km이면 반경 2km, 지름 4km다. 시설을 모두 방문하는 것이 아니라 원 안의 모든 시설을 경로 생성에 반영한다.

중점은 위도와 경도의 산술 평균으로 계산한다. 직선거리는 지구 반경 6,371,000m를 사용하는 Haversine 공식으로 계산한다. 한국 내 보행 목적을 대상으로 하며 국제 날짜변경선을 넘는 경로는 지원 대상으로 검증하지 않았다. 시설 포함 여부도 중점에서의 Haversine 거리 ≤ 2d로 판정한다.

기존에는 이미 제공된 도보 후보의 주변 시설만 세었다. 변경 후에는 원 안의 CCTV와 보안등 전체를 먼저 추출하고, 시설 분포로 우회 경유지 후보를 생성해 도보 경로 API에 전달한다. 지도 마커의 표시 개수 제한은 경로 계산에 적용하지 않는다.

시설 원본은 이전 작업에서 검증한 CCTV 251,987개, 보안등 28,652개 좌표다. 실제 반영되는 시설 수는 검색마다 원 안의 개수로 결정되며 화면 안내에도 반경과 CCTV·가로등 개수를 표시한다. 자료가 없는 시설은 만들어 넣지 않는다.

핵심 파일: location/FacilityRoutePlanner.kt(신규), location/NavigationRepository.kt, location/SafetyRepository.kt. 원형 탐색·우회 후보 테스트는 FacilityRoutePlannerTest.kt에 추가했다.

# 시설 분포에서 보행 경로를 만드는 과정

1. 원형 범위를 33×33 격자로 근사한다. 격자 간격은 반경/16이다. 원 안의 모든 시설을 해당 격자에 누적하며 CCTV는 4, 보안등은 1의 가중치를 준다. 시설을 임의로 상위 몇 개만 잘라 사용하지 않는다. 격자 대표 경유점은 중심에 가장 가까운 실제 시설 좌표를 우선 사용한다.

2. 각 격자의 시설 가중치는 주변 8개 격자의 가중치와 함께 부드럽게 누적한다. 주변 영향은 1/(1+|dx|+|dy|)로 줄인다. 경계의 모든 시설도 누적 대상이다. 이것은 실제 밝기·범죄위험도 모델이 아닌 로컬 휴리스틱이다.

3. 원 내부 격자 사이의 8방향 연결에 Dijkstra 탐색을 적용한다. 간선 비용 = 이동 격자거리 × [(1-w)+w/(1+F)]이며 F는 두 끝 격자의 평균 시설 가중치다. w=0.98, 0.75, 0.5의 세 설정으로 시설 우회 성향이 다른 후보를 생성한다. 시설이 많을수록 비용이 낮아져 짧은 직선 밖의 밀집 구간으로 우회할 수 있다. 모든 비용은 양수여서 이득을 위한 무한 순환은 생기지 않는다.

4. 격자 탐색 결과의 방향 전환점을 추린 뒤 내부 경유지를 최대 23개로 줄인다. 출발·도착을 합해 최대 25개다. 초과하면 방향 전환점을 균등 간격으로 추출하므로 세부 굴곡은 근사된다. 결과가 같은 경유지 후보는 중복 제거한다.

5. 기존 기본 도보 경로 조회 1회에 더해 최대 3회의 경유지 도보 조회를 수행한다. API는 mapbox/walking, geometries=geojson, overview=full, steps=true를 유지한다. 기본 조회는 대안 경로를 요청하고 경유 후보 조회는 alternatives=false를 사용한다. 각 요청의 연결·읽기 제한시간은 각각 5초다.

6. 시설 격자의 연결선은 도로가 아니다. 지도에는 격자 직선을 표시하지 않고 API가 실제 보행 경로로 반환한 GeoJSON만 사용한다. 조회 실패 후보는 제외하고 부분 실패를 안내한다. 반환 경로의 모든 좌표가 원 안에 있는지 검사하며 원 안의 보행 경로가 전혀 없으면 오류로 남긴다.

공식 API 근거: Mapbox Directions v5 walking은 출발·도착을 포함한 최대 25좌표의 경유지 요청을 지원한다. https://docs.mapbox.com/api/navigation/directions/

# 최종 평가·검증·한계

최종 후보는 기본 조회와 시설 우회 조회 결과를 합친 뒤 GeoJSON 중복을 제거한다. 후보 경로 평가에도 동일한 원 안의 시설 목록만 사용한다. 경로 인근 CCTV(50m), 보안등(40m)을 집계하며 한 시설은 여러 구간에 가까워도 한 번만 센다.

시설 지표 D=(4×CCTV 수+보안등 수)×1000/max(경로 길이 m,100). 안전 경로는 D 최대를 선택하고 동점에서만 예상 시간이 짧은 경로를 선택한다. 최단은 예상 시간 최소를 선택한다. API 시간이 없으면 1.2m/s 보행 속도로 추정한다.

추천은 후보 내 최소·최대 기준으로 시설 지표 S와 시간 효율 E를 0~1로 정규화하고 0.5S+0.5E가 최대인 경로를 선택한다. 정규화 범위가 0이면 해당 차이를 0으로 처리한다. 카드 순서는 추천 → 안전 → 최단이며 추천이 기본 선택이다.

실제 API 키와 휴대폰으로 장소별 경로를 조회하는 온라인 종단 테스트는 이번 변경에서 수행하지 않았다. API 도로망·시설 좌표 정확도, 경유지의 보행 도로 스냅, 통행 제한 및 장거리 성능은 실기기에서 확인해야 한다. 좌표를 모두 방문하는 경로는 아니다.

한계: 격자는 보행 도로망 자체가 아니고, 후보를 제한된 수의 경유지로 압축하므로 원 안의 모든 가능한 보행 경로를 전수 탐색하지 않는다. 가중치·반경은 안전성 실증 모델이 아니며 시설 밀도가 높아도 실제 안전을 보장하지 않는다. 시설이 없는 긴 구간을 다른 구간의 밀집도가 상쇄할 수도 있다. 정확한 도로 구간별 최적 안전 경로에는 보행 그래프와 구간별 위험 모델이 추가로 필요하다.
