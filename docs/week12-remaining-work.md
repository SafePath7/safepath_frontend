# 12주차 구현 및 확인 사항

## 구현

- 보호 중 목록: 위치 채널의 상태를 받아 위험상황, 위험 의심, 안전, 미확인 순으로 정렬한다. 상태 보기 권한이 없는 보호자에게는 상태를 표시하지 않는다. 연결이 끊기면 미확인으로 바꾸고 재연결한다.
- 보호자 지도: 상세 화면을 연 이후 수신한 위치를 실제 이동 궤적으로 표시한다. 앱 화면을 열기 전의 이력은 서버에서 제공하지 않으므로 표시하지 않는다.
- 5초 위치 수집 요청과 로컬 위치 대기열, 전송 재시도, 세션 시작 및 PIN 종료는 기존 구현을 사용한다.

## 실기기 확인

1. 서로 다른 두 계정으로 보호자 연결 후 귀가 세션을 시작한다.
2. 보호 중 목록에서 상태 권한이 있는 사용자와 없는 사용자의 상태 표시 및 위험 우선 정렬을 확인한다.
3. 상세 화면을 열고 이동하며 실제 수신 좌표가 경로로 표시되는지 확인한다.
4. 귀가자 기기의 네트워크를 끊고 이동한 뒤 복구하여 위치 재전송 및 보호자 재연결을 확인한다.
5. PIN 오류, 다섯 번째 실패 안내, 올바른 PIN 종료 및 도착 시 자동 종료되지 않는 동작을 확인한다.

## 서버 계약·팀 결정이 필요한 항목

- 현재 서버의 세션 시작 DTO에는 guardianIds와 selectedRoute만 있다. PIN은 기기에서 검증하며 감지 설정은 세션 시작 요청으로 전송하지 않는다. PIN 서버 저장이나 설정 전달은 별도 API·보안 계약이 필요하다.
- 상세 화면을 열기 전의 전체 이동 이력은 백엔드 조회 API가 없어 복원할 수 없다.
- 5초는 현재 앱의 위치 수집 요청 간격이며 팀의 TBD-1 확정값이 확인되면 그 값에 맞춘다.
